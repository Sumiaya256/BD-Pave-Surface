# BD-PaveSurface repository documentation

## Dataset
**BD-PaveSurface: A Multi-Weather Pavement Surface Image Dataset for Crack, Pothole, and Good Pavement Condition Assessment in Bangladesh**

- Repository: Zenodo
- DOI: `10.5281/zenodo.21855576`
- License: Creative Commons Attribution 4.0 International (CC BY 4.0)

## Dataset composition
The dataset contains **21,000 stored image files** in two components:

- **9,000 raw field images**: 3,000 Crack, 3,000 Good, and 3,000 Pothole images.
- **12,000 processed/augmented files**: standardized 224 × 224 RGB versions of all 9,000 cleaned original images plus **3,000 newly generated training-only augmented images** (1,000 per class).

The 21,000 stored files therefore do **not** represent 21,000 independent field captures. The processed component includes standardized versions of the same 9,000 cleaned original field images.

## Class definitions
- **Crack**: pavement images with visible surface cracking, including linear, longitudinal, transverse, and interconnected crack patterns.
- **Pothole**: images showing localized pavement surface failure, including dry and water-affected potholes.
- **Good**: pavement images without visually dominant cracks or potholes; normal texture, dust, shadows, lane markings, color variation, or minor roughness may still be present.

When more than one pavement condition is visible, the image-level label follows the dominant visible pavement condition.

## Image-level metadata
`BD_PaveSurface_Final_Metadata.csv` provides metadata for the 9,000 cleaned original images with the fields:

`image_id`, `filename`, `class`, `season`, `camera_device`, and `collection_date`.

Seasonal coverage is:
- Rainy season: 2,575 images
- Winter: 2,300 images
- Summer: 4,125 images

Camera-device metadata contains:
- vivo X200 Pro: 4,005 images
- iPhone 15 Plus: 3,534 images
- Redmi K50i: 1,461 images

### Metadata provenance and limitations
The metadata fields were compiled from the available survey records and dataset organization and should not be interpreted as uniformly recovered EXIF metadata. Exact per-image GPS/road-section coordinates, standardized instantaneous weather labels, quantitative illumination or surface-wetness measurements, and independently verified capture dates are not available for all images. The `season` field records the field-survey seasonal category; no separate instantaneous weather label is asserted.

## Scene-level split protocol
The 9,000 cleaned original images were grouped within class using L2-normalized ImageNet-pretrained ResNet50 penultimate features and cosine similarity with threshold **0.95**. Complete scene groups were assigned to one split only.

Original-image split:

| Split | Original images | Per class |
|---|---:|---:|
| Train | 6,300 | 2,100 |
| Validation | 1,350 | 450 |
| Test | 1,350 | 450 |

Only the training split was augmented. After adding 1,000 augmented images per class, the processed dataset contains:

| Split | Total files |
|---|---:|
| Train | 9,300 |
| Validation | 1,350 |
| Test | 1,350 |
| **Total** | **12,000** |

Validation and testing contain only standardized original images and are not augmented.

`split_summary.csv` summarizes the **pre-augmentation original-image split** and scene-group counts. Therefore its `augmented_images` field is 0 for train/validation/test; the 3,000 training-only augmented images are created later in the workflow.

## File-naming rules
Standardized original files generated by the notebook use:

`orig__<five-digit-row-number>__<original-stem>.jpg`

Example: `orig__00042__crack0123.jpg`

Training-only augmented files use:

`aug__<four-digit-augmentation-number>__parent_<original-stem>.jpg`

Example: `aug__0042__parent_crack0123.jpg`

## Preprocessing
All cleaned original images are converted to RGB and resized directly to **224 × 224** pixels. JPEG outputs use quality 95 with subsampling 0.

## Training-only augmentation
The notebook generates the additional training images using:

- Random resized crop: 224 × 224, scale 0.75–1.00, aspect ratio 0.90–1.10
- Horizontal flip: probability 0.50
- Rotation: up to ±12°, applied with probability 0.70
- Perspective transformation: distortion scale 0.15, probability 0.25
- Color jitter: brightness 0.20, contrast 0.20, saturation 0.10, hue 0.02
- Gaussian blur: kernel 3, sigma 0.1–1.0, probability 0.20
- Random erasing: probability 0.25, scale 0.01–0.05, ratio 0.3–3.3

The finalized generation stream uses fixed seed **17**.

## Leakage and checksum checks
- Complete similarity-based scene groups are kept within a single split.
- Scene-group overlap across train/validation/test: **0**.
- `strict095_sha256_cross_split_audit.csv` contains a SHA-256 value for each of the 9,000 cleaned original image files.
- Exact SHA-256 hashes occurring in more than one split: **0**.

The SHA-256 audit is specifically a **cross-split leakage check**; the conclusion above concerns whether an identical file occurs in different splits.

## Baseline validation protocol
Four ImageNet-pretrained CNNs were evaluated: ResNet50, DenseNet121, MobileNetV2, and EfficientNetB0. For each architecture, pretrained backbone parameters were frozen and the final classifier was trained for the three-class task. Training used Adam, cross-entropy loss, learning rate `1e-4`, weight decay `1e-4`, batch size 16, maximum 30 epochs, and early stopping patience 10. The best checkpoint was selected using minimum validation loss and reloaded for final evaluation on the untouched 1,350-image test subset.

The completed run used fixed seed **17**.

## Running the notebook

3. Update `RAW_ROOT` and `PROJECT_ROOT` in the configuration cell.
4. Install the packages listed in `requirements.txt`.
5. Run the notebook from top to bottom.

The displayed notebook outputs correspond to the completed Windows run and may show the original local F: drive paths.
